# Contributing
Read charter, architecture and AGENTS.md. Claim a ready issue; confirm dependencies are merged. Branch `task/<id>-<slug>` from main. Keep changes scoped, write tests and docs, report security/performance/compatibility impact, submit PR linked to issue. Do not merge your own PR. Propose contract or schema changes through ADRs first. Reviewers reproduce tests and check acceptance criteria. Follow respectful conduct; report security privately. No generated code without review and provenance where required.

Security rules: never commit credentials, tokens, private keys or real user data, and redact them from logs, fixtures and issue text. Pin every third-party workflow action to a full commit SHA — the policy job fails otherwise. Keep workflow token permissions least-privilege. Every security control you add or touch needs a negative test that fails closed, and any change to a trust boundary, entry point or credential type updates [the threat model](docs/THREAT_MODEL.md) in the same pull request. New runtime dependencies require justification and review; do not add one to fix a problem a few lines of code can solve. Report a vulnerability through [the security policy](SECURITY.md), not a public issue.

# GitHub setup
1. Confirm license, repository owner, project name and governance. Create an empty repository (no generated README).
2. Extract ZIP, enter QuestionAnswer, `git init -b main`, `git add .`, `git commit -m "Initialize QuestionAnswer project"`, `git remote add origin https://github.com/OWNER/QuestionAnswer.git`, `git push -u origin main`.
3. Enable private vulnerability reporting, branch protection/rulesets (PR required, independent approval, required checks, no force push), restrict release and signing credentials, add real CODEOWNERS after assigning maintainers. Enable dependency and secret scanning where available. Review/pin CI action SHAs before trusting privileged workflows; starter uses version tags.
4. Authenticate GitHub CLI locally. `python3 tools/import_issues.py --repo OWNER/QuestionAnswer --milestone M0` previews; add `--apply` to create. Remove milestone filter for entire backlog. Script skips existing IDs found among up to 1000 issues; run sequentially, not concurrently. It does not create GitHub milestone objects, labels, issue dependencies or projects; dependency IDs and milestone names are in issue bodies. Configure these manually or via verified integration.
5. Create GitHub Project with Status, Task ID, Workstream, Priority, Milestone, Owner, Dependencies, Reviewer, Evidence. States: Backlog, Specification, Ready, Assigned, Implementation, Review, CI, Blocked, Merged. Assign only approved ready tasks; use Colnera for orchestration if supported. Import CSV/JSON only if Colnera supports the format; no proprietary import schema assumed.
6. Refine task-specific acceptance tests before assignment. M0 specifications first, then framework. CI starter is not a full quality pipeline; expand it in GOV-006. No repository or remote changes were made by this package.

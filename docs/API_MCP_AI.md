# API, MCP and AI
REST `/api/v1` with OpenAPI contract, JSON, RFC 9457-style errors, scopes, resource authorization, cursor pagination, filtering, idempotency, rate limits and signed webhooks. Endpoints: questions, answers, clarifications, search, topics, users, collections, feedback; admin endpoints restricted. MCP protocol/transport/authorization conformance must be verified against official version selected in an ADR. Begin read-only search/get tools and resources with stable IDs; later scoped write tools propose answers, submit feedback and clarifications. External MCP client optional, SSRF protections and explicit approval for sensitive actions. AI provider-independent interface, opt-in configuration, cost limits, timeouts, provenance, citation verification, redaction, drafts and human editorial approval. No AI required for baseline installation. Full-text search baseline, semantic retrieval optional.

Localization: reads accept an explicit `locale` parameter and otherwise negotiate `Accept-Language`; responses carry `Content-Language` and disclose the resolved locale, whether a fallback was used and the translation status. Writes require an explicit locale — a missing one is a validation error, never a guess. MCP read tools take a `locale` argument; MCP writes may submit a translation draft but cannot publish it. AI generation receives the target locale and returns machine drafts with provenance. See [localization](I18N.md).

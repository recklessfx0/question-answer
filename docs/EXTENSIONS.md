# Extension contracts
Versioned manifest: ID, name, version, type, core/PHP compatibility, dependencies, entrypoint, license and declared capabilities. Extension types: plugins, themes, modules, widgets, providers, adapters, MCP tools, languages. Lifecycle discover → validate → stage → install/migrate → activate → disable/update/uninstall. Stable public hooks, events, service registration, routes, admin navigation, template slots, migrations and diagnostics. No core file edits. Signed packages, dependency checks, safe mode and recovery. PHP extensions execute with application privileges; capability declarations are informational unless enforced by specific APIs. Provide SDK, examples and contract tests. Marketplace deferred.

The `languages` type is the exception to executable extensions: a language pack ships locale metadata and message catalogues only — no entrypoint, no PHP, no hooks. It is signed and versioned like any other package, contributes keys through the documented precedence, resolves key conflicts by declared order rather than load order, and uninstalls without orphan keys. See [localization](I18N.md).

Performance: extension routes, services, hooks, templates and locales are declared in the manifest and compiled into the deploy artifacts at install, so nothing is discovered per request and no listener is instantiated unless registered. A cost budget applies — an extension that exceeds the page query budget or render budget fails the build rather than degrading production. See [framework performance](FRAMEWORK_PERFORMANCE.md).
